# Уровни вместо классов

Дата: 2026-08-06

## Задача

Заменить понятие «класс» (сынып, 1–4) на «уровень» (деңгей). Один уровень —
это одна книга: уровень 3 — «Даниел Дефо Робинзон Крузо», уровень 4 — книга
для четвёртого уровня. Уровень открывается после прохождения предыдущего.
Учитель назначает книге уровень и может открыть ученику уровень вручную.
В панели учителя нужно удобно работать с книгой из десятков частей.

## Ограничения

База боевая: 4 книги, 68 частей, 21 ученик, 88 попыток. Названия книг, тексты
частей, вопросы, попытки и оценки менять нельзя. Ученик, прошедший 28 частей
из 29, после выката должен видеть ровно то же, что видел до него.

## Модель данных

Миграция `supabase/migrations/0003_levels.sql`:

| Было | Стало |
|---|---|
| `books.grade int not null default 1 check (1..4)` | `books.level int not null` + `unique (level)` |
| `students.grade int null check (1..4)` | `students.start_level int not null default 1` |
| `enrollments` | удалена (не используется с первой версии) |

Перенос значений один в один: `level = grade`, `start_level = coalesce(grade, 1)`.
Ограничение «1–4» снимается — уровней столько, сколько книг.

Уникальность `books.level` кодирует «один уровень = одна книга».

## Доступ ученика к уровням

Экран выбора класса (`ClassPicker`) удаляется. Главный экран мини-приложения —
список всех книг по возрастанию уровня, каждая с прогрессом или замком.

Правило открытия (`src/lib/progress/levelUnlock.ts`, чистая функция):

```
unlockedThrough = student.startLevel
пока книга уровня unlockedThrough существует,
      имеет хотя бы одну часть,
      и все её части в статусе completed:
    unlockedThrough += 1

уровень открыт  ⟺  level <= unlockedThrough
```

Книга без частей не считается пройденной — иначе пустой уровень открывал бы
следующий. Часть считается пройденной по существующему `computePartStatus`
(статус `completed`), логика статусов не меняется.

Внутри книги части по-прежнему открываются последовательно
(`src/lib/progress/unlock.ts`, без изменений).

## Панель учителя

### Список книг (`/teacher/books`)

- Карточки отсортированы по уровню, на каждой чип `N-деңгей`.
- Стрелки ↑/↓ меняют книгу местами с соседней по уровню.
- Форма создания книги не спрашивает уровень: новая книга получает
  `max(level) + 1`.

### Страница книги (`/teacher/books/[bookId]`)

- Блок «уровень» вместо блока «класс»: селект со списком 1…N. Выбор занятого
  уровня меняет две книги местами (обмен значениями `level`), а не падает с
  ошибкой уникальности.
- Массовое добавление частей: поле «сколько частей» (1–50) создаёт пустые части
  с заголовками `K-бөлім`, продолжая существующую нумерацию.
- Компактный список частей: строка — номер, название, число вопросов, кнопки.
  Редактирование текста разворачивается по клику.
- Стрелки ↑/↓ у части меняют её местами с соседней.

### Ученики (`/teacher/students`)

Блок «сменить класс» заменяется на «стартовый уровень»: селект 1…N. Так учитель
открывает ученику доступ, минуя лестницу.

### Обзор (`/teacher`)

Вместо «класс не выбран / N класс» показывается доступный ученику уровень и
прогресс по книгам этого уровня и ниже.

## Обмен значениями при уникальном ограничении

`books.level` и `parts.(book_id, order)` уникальны, поэтому прямой обмен
двух значений нарушает ограничение на промежуточном шаге. Обмен делается в три
запроса через временное отрицательное значение:

```
A.level → -1
B.level → старый A.level
A.level → старый B.level
```

Функции `swapBookLevels(idA, idB)` в `src/lib/db/books.ts` и
`swapPartOrder(idA, idB)` в `src/lib/db/parts.ts`.

## Терминология

Везде в интерфейсе `сынып` → `деңгей`. Формат подписи: `3-деңгей`. Название
книги везде берётся из `books.title` — отдельного имени уровня нет, поэтому
добавленная книга автоматически подписана своим названием.

`src/lib/options.ts`: `GRADES`/`gradeLabel` → `levelLabel(level) => "N-деңгей"`.
Фиксированного списка уровней больше нет — он строится из списка книг.

## Тесты

Новые unit-тесты (vitest, без сети):

- `src/lib/progress/levelUnlock.test.ts` — стартовый уровень, лестница вверх,
  пустая книга не открывает следующий уровень, книга с непроверенными
  открытыми вопросами (`pending_review`) не открывает следующий уровень.

Существующие тесты `partStatus`, `unlock`, `bookProgress`, `mappers` остаются;
`mappers.test.ts` правится под переименование полей.

Проверка: `npm test`, `npm run lint`, `npm run build`.

## Что не делается

- Не меняются: тексты книг и частей, вопросы, попытки, оценки, вход учеников,
  вход учителя, проверка открытых ответов.
- Не добавляется: обложка книги, произвольное имя уровня отдельно от книги,
  перетаскивание мышью (только стрелки).
